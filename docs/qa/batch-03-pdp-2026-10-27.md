# Batch 03 — PDP responsive delivery

Starting commit: `78a6e9d`; working tree was clean. Presentation-only changes;
purchase callbacks, options, validation, mapping, APIs and state are unchanged.

## Fixed

| Confirmed issue | Change |
| --- | --- |
| Positioned footer links paint over the fixed PDP purchase button because `main` is isolated | Mark the PDP container and raise **only that page's** main stacking context, following the existing Cart pattern. Header menus, modal layers and mobile navigation remain above it. |
| Reviews anchor lands at y=0 underneath the 69px desktop purchase bar | Add the existing 96px spacing token as the reviews section's desktop scroll margin. Heading now lands at y=96. |
| An unbroken option label grows the fieldset to 293px inside a 288px mobile container | Constrain fieldset/buttons and allow label wrapping, with padding for multiline text. |
| A deliberately large Arabic price is clipped inside the 132px mobile price slot | Allow the purchase row to wrap, preserving the full price and a full-width CTA when necessary. |

The latter two are **browser-only long-content stress cases**, not claims that
the sampled catalogue currently contains those labels/prices. No API data was
changed. Ordinary labels/prices continue to fit a single row where space permits.

The real gallery uses contained images and a bounded thumbnail scroller; inspected
layouts, long real titles, quantity controls and personalization did not justify
a redesign. No gallery or shared ProductCard changes were made. No Buy Now action
exists in the inspected PDP; none was invented.
